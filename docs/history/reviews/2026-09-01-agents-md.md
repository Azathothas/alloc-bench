## Pass 1 - the door sweep

**"What other path reaches a reader, and does every entry point route
correctly?"**

 **What this pass looked at that the others did not:** the *entry points*. Not
whether a link resolves (pass 2 automates that) or whether a claim is true (pass
3), but whether a reader arriving by each available route reaches the right file.

Enumerated entry points, then grepped for the ones not enumerated:

```sh
find . -path ./.git -prune -o -path ./references -prune -o \
  \( -iname 'AGENTS.md' -o -iname '.cursorrules' \) -print
```

##  Added after the fact: what all three passes missed

**The claim audit swept `docs/AGENTS.md` and the pages it routes to. It did not
sweep the record this session was itself writing.**

`docs/history/todo/PROGRESS.md`'s measured baseline carried the line *"No Docker or Podman
daemon was reachable"*. **No probe was ever run.** The client was installed and
the daemon was simply not started - the case
[`../../containers.md`](../../containers.md) documents with a one-line fix, in a
section stating that an environment with no init is *where this project was
actually developed*. `alloc-bench doctor` afterwards: **0 problem(s)**.

 **Three lenses ran and none fired on it**, because each was pointed at the
tree and none at the session's own output. Lens 3 asks *"which sentence in what I
am about to publish is not backed by an artefact I can point at?"* - and the
answer was sitting in the file the next session was told to read first.

 **The cost was not the sentence.** A work order for an *unattended* successor
was scoped around it, claiming only ~2.0 of 6.5 L-equivalents were reachable and
naming five entries as out of reach. A session trusting it would have skipped
work it could have done, with no reason to doubt a line that looked measured.

 **The rule that comes out of it, now mechanical rather than remembered:**
`sh scripts/gate.sh` runs `alloc-bench doctor` and prints its verdict every time,
so a capability is a measured line and never a belief.
[`../todo/RULES.md`](../todo/RULES.md) §4 carries both this and the
piped-exit-code error that reinforced it.

 **For the next reviewer: add a fourth pass over your own record**, and ask of
every line in the baseline table *"what command produced this number?"*. A pass
that only audits the tree will miss the one file the next session is guaranteed
to read.
