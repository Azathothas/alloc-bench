# Git

- Work on a named branch and keep unrelated changes out of it.
- Use the configured Git name and email. Do not add model, tool, or vendor
  attribution.
- Write imperative commit subjects. Use the body for constraints that are not
  visible from the diff.
- Inspect staged changes before committing.
- Never commit credentials, local caches, build output, or unreviewed generated
  files.
- Push only with explicit authorization and to the named destination.
- Do not force-push shared history unless the task explicitly requires it.
- Preserve published result data; document any mechanical migration applied to
  it.
