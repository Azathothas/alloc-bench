# Prose

Write for someone making or reviewing a technical change.

- Lead with the fact, command, or constraint.
- Prefer short sentences and concrete nouns.
- Use present tense for current behavior.
- State scope and uncertainty beside each result.
- Replace adjectives with evidence. Avoid marketing language, filler, emojis,
  warnings made from capitalization, and em dashes.
- Explain why only when it changes implementation or interpretation.
- Keep incident narratives and completed work in `docs/history/`.
- Do not mention writing tools or add generated-by attribution.

Claims must be reproducible from code, committed evidence, or an authoritative
upstream source. If the evidence is incomplete, say so directly.
