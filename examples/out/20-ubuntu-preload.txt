=== 2. does the library you just built actually export an allocator? ===
 nm -D, not nm. The DYNAMIC symbol table is what ld.so resolves
   against; a library can define malloc in .symtab and export nothing.

  mimalloc's own prefixed API is there too, which is how you know it is mimalloc:
     T mi_free

     T mi_realloc
     T mi_version

=== 4. the check that the ENVIRONMENT VARIABLE is not the evidence ===
 mimalloc will tell you about itself if asked. MIMALLOC_VERBOSE=1 prints
   its banner from inside the process -- a second, independent witness
   that does not depend on reading /proc:

     mimalloc: process init: 0x7FB6938AB780
     mimalloc: reserved 1048576 KiB memory
     mimalloc: process done 128

 Not every allocator has such a banner, which is why residency is the
  check the harness relies on: it works for all of them.

=== what this example establishes ===
 An allocator built from source at a pinned commit can be preloaded into
   an unmodified dynamic binary on Ubuntu, and both the export check and
   the residency check confirm it is the file that was built here.
 It does not establish that it is faster. On glibc this project measured
   preloaded mimalloc at 1.194x the control -- 19.4% SLOWER, outside its
   own 2.9% MAD -- in results/published/2026-09-03-preload-x86_64-all-eight/.
